1. random_int_list() is O(n), where n is the length argument.
It makes n calls to randint(), and each call takes constant time, so the
total work grows linearly with n.
 
2. time_trial() is O(t*n + n log n), where t is num_trials and n is data_size.
- Building the random list: O(n)
- t linear searches, each O(n) worst case: O(t*n)
- Sorting the copy once: O(n log n)
- t binary searches, each O(log n): O(t log n)
The t*n term from the linear searches and the n log n term from the sort
dominate, so the total is O(t*n + n log n).
 
3. Answer: 32 searches.
N = 10,000, and every search fails (worst case).
Linear search per search: 5 * N = 50,000 instructions.
Binary search per search: 10 * log2(N) = 10 * 13.29 = 132.9 instructions.
Sorting once: 12 * N * log2(N) = 12 * 10,000 * 13.29 = 1,594,524 instructions.
Sorting + binary search wins when:
  50,000k > 1,594,524 + 132.9k
  49,867.1k > 1,594,524
  k > 31.97
So you need at least 32 searches.
Check: at k = 32, linear = 1,600,000 and sort + binary = 1,598,776,
so binary is cheaper. At k = 31, linear = 1,550,000 and sort + binary =
1,598,643, so linear is cheaper.
